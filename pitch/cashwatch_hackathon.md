# Ручная проверка видео плохо масштабируется
layout: problem
rubric: R1, R2, R6
stat: 5 минут | лимит на обработку одного видео
source: Кейс_ForteBank.docx, разделы 1–4 и FAQ 14
time: 25
notes: "Задача банка — проверить кассовую дисциплину по записи и не потерять событие среди обычных действий. По условиям соревнования на ролик есть пять минут, а жюри может отправить несколько роликов. Нужны доказательство и объяснение, которые человек сможет проверить."
Проверяющему нужен конкретный эпизод с доказательством, а не общий вердикт по ролику.
- На входе только видео, без звука и распознавания лиц.
- В финале возможны новый ракурс и ранее не встречавшиеся типы нарушений.

# Каждый вывод можно проверить по кадру и норме
layout: pipeline
rubric: R2, R3, R4

time: 30
notes: "Мы разделили наблюдение и правовую интерпретацию. Модель описывает видимые факты, затем база прецедентов и правила выделяют кандидата. Юридические цитаты система прикрепляет из проверенного реестра: VLM не сочиняет номер документа или пункта."

- Событие | тип и таймкод
- Доказательство | 1–3 кадра и описание
- Основание | цитата из проверенного реестра

# Демо: из видео — проверяемый инцидент
layout: terminal
rubric: R1, R2, R3, R4, R7
source: cashwatch/README.md, раздел API; Кейс_ForteBank.docx, раздел 10
window: CashWatch API · формат ответа
takeaway: Во время показа открыть результат в веб-интерфейсе: таймкод, кадры, описание и норму.
time: 65
notes: "Здесь демонстрируем работающий интерфейс: загружаем видео, ждём завершения задания и открываем найденный эпизод. Обратите внимание на кадры и таймкод, затем на описание видимого действия и точную нормативную ссылку. Слайд показывает структуру API как резерв на случай, если живая демонстрация недоступна."
```text
POST /api/v1/analyze       → job_id
GET  /api/v1/jobs/{id}     → status: done
verdict                   → violation / no_violation
violations[].type         → тип нарушения
violations[].timecode_sec → секунда события
violations[].evidence_frames → 1–3 JPEG-кадра
violations[].rule         → проверенная цитата нормы
```

# Три слоя знаний выдерживают новые условия
layout: architecture
rubric: R3, R4, R5, R7
source: README.md; knowledge/PRESENTATION.md, разделы 3–5; rag/README.md
time: 40
notes: "В обучающей выборке нет готовых меток типов, поэтому закрытый классификатор ограничил бы ответ известным списком. Мы храним наблюдаемые факты, примеры нормальной работы и нормативную базу отдельно. Для известного типа используем проверенную цитату; для необычной ситуации поиск предлагает кандидата, который требует проверки человеком."

- Прецеденты: 40 видео учат отличать нарушение от нормальной работы
- Нормы: реестр проверенных цитат и локальный поиск по 313 актам
